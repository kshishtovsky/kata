# EXP-0068 — hold q in registers across the position loop

**Status:** PASSED, kept
**Hypothesis:** EXP-0067 showed the isolated score shape reaches 79 GMAC/s (99% of
the fp32 core peak) while the same work inside `prefill_group4` measures 52, so
the engine loses ~35%. The isolated arm keeps the four q registers live; the
engine reloaded them 16 times per position (4 heads x 4 zmm).

## Change

`src/prefill.cpp` `prefill_group4`: the per-group q vectors are hoisted into
`__m512 qr[G][4]` before the position loop, and the inner block becomes
`v = mul(qr[h][0], k0); v = fmadd(qr[h][1], k1, v); ...` instead of
`_mm512_loadu_ps(qq + 16*r)`.

Register budget: `qr[4][4]` = 16 zmm, `acc[4][4]` = 16 zmm, plus `k0..k3` and
temporaries. Zen 4 has 32 architectural zmm and GCC's `(rsp)` references in the
function stay at **1** (measured with `objdump -d ... | grep -c 'rsp)'`), so
nothing spills — the accumulators and the q live in the same 32 registers only
because `qr` replaces the four `a[G]` temporaries that used to hold the dot
products.

## Note

This is the first prefill-attention change that is both lossless and above the
noise floor since EXP-0065. It also closes the gap EXP-0067 opened: the engine
now runs the score pass at ~60 GMAC/s against the 79 of the isolated shape, so
the remaining headroom on QK is ~1.3x and it is arithmetic (`vpdpbusd` is dead,
see EXP-0067).
