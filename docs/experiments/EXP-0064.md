# EXP-0064: folding the min pass into the main loop spills into memory

Status: REJECTED (two variants measured, both reverted)

## Hypothesis

EXP-0063 left one lead: `q4_K_vnni_tile` reaches 54% of the VNNI peak while an
isolated copy of its inner loop reaches 87%, and the difference is the staging
around it. The most obvious waste is that `tb.bsum[s]` is read in a **second**
sweep over all 8 sub-blocks after the value sweep has already finished, so the
band is walked twice.

## Variant A: int accumulators, one pass

`__m512i s1[VRN], s2[VRN]` declared together, both updated in the value loop
where `bsum` is still hot.

| | m=256 | m=512 | m=1024 | stack refs |
|---|---|---|---|---|
| baseline | 2292.6 (46.1%) | 2718.5 (54.6%) | 2691.2 (54.1%) | 18 |
| A | 2187.9 (44.0%) | 2483.2 (49.9%) | 2660.9 (53.5%) | **46** |

Adding 8 live `s2` registers to 8 `s1`, 8 `a16` and 8 `acc` exceeds the register
file, GCC spills, and 18 stack refs become 46.

## Variant B: float accumulators, one pass

Same fusion, but `s1f`/`s2f` are float and fed by `cvt+fma` instead of
`vpmulld`, which was supposed to free int registers. `a16 <= 61k` and
`sc <= 63` are exact in float32, so only the sum over 8 sub-blocks rounds.

| | m=256 | m=512 | m=1024 | stack refs |
|---|---|---|---|---|
| baseline | 2292.6 (46.1%) | 2718.5 (54.6%) | 2691.2 (54.1%) | 18 |
| B | 2182.2 (43.9%) | 2663.4 (53.5%) | 2668.7 (53.6%) | 29 |

Better than variant A but still under baseline, and still spilling 29 times
versus 18. `Gemm*` tests passed in both variants, so these are pure
performance verdicts.

## What the numbers say

The two-sweep structure is not waste: it is what keeps the register set inside
32 zmm. Any fusion that needs `s1` and `s2` live simultaneously loses more to
spills than it gains from one fewer pass over 8 `bsum` vectors, which are 1 KB
that stays in L1 anyway.

| m | baseline | A | B |
|---|---|---|---|
| 256 | 46.1% | 44.0% | 43.9% |
| 512 | 54.6% | 49.9% | 53.5% |
| 1024 | 54.1% | 53.5% | 53.6% |

Baseline restored from `/tmp/gemm_s2base.cpp`, 105/105 tests green, 18 stack
refs re-confirmed.

## Conclusion

The 54%-of-peak figure is a register-budget limit, not a structure limit:
`acc[8] + s1[8] + a16[8] = 24` live zmm is already at ~28 with scratch
(EXP-0063, reviewer-verified), so there is no room to shorten the loop without
changing what lives in registers. Options that would change that are all
format changes (pack weights so `a16` disappears, or split the sub-block scale
into the accumulator), and EXP-0062 already measured the one cheap format
change as a wash.
