# EXP-0081 — what one CPU↔GPU handoff costs

**Status:** PASSED
**Date:** 2026-11-27

## Problem

EXP-0080 priced a hybrid decode with expert residency and found 2.3x at an 8 GB
budget — but it charged nothing for moving control between devices. A hybrid
needs the token to bounce once per layer: the GPU finishes the attention /
fixed-weight part, the CPU needs that output to run the router and its experts,
and the GPU needs the expert sum back before the next layer can start. At 40
layers that is 40 round trips per token, and if each costs 40 us the tax alone is
1.6 ms — 19% of an 8.6 ms token, or a third of the win at a 2 GB budget.

So the number had to be measured, and the cheapest mechanism chosen.

## Method

`bench/hip/bench_handoff.hip` and `bench/hip/bench_handoff_probe.hip`
(`hipcc -O3 ... -o /tmp/handoff`). Payload is the one that actually crosses: the
2048-float residual row. Each arm is a loop over 1000-2000 handoffs, timed with
`hipEvent` pairs; the 40-layer chain arms include a dependent host operation
between switches, so the host cannot run ahead and hide the latency.

## Results

| Mechanism | us per switch |
|---|---|
| pageable `D2H` + `H2D`, no kernel | 46.63 |
| pinned `D2H` + `H2D`, no kernel | 33.23 |
| tiny kernel + `hipStreamSynchronize`, no copy | **19.72** |
| pinned `D2H` + kernel + `H2D` (sync) | 47.42 |
| pinned async `H2D` + kernel + async `D2H` + sync | 31.00 |
| **zero-copy: kernel on mapped host memory, no copy, no sync** | **11.23** |
| **zero-copy + sync (what the CPU actually waits for)** | **28.48** |
| 40-layer chain, pinned async/sync (one token) | 1240.34 us |
| 40-layer chain, zero-copy + sync (one token) | 1113.94 us |

## Conclusion

- Launch-and-wait on an empty stream is **19.7 us**. That is the floor for any
  design that synchronises per layer, and it is a driver property on this
  platform, not something the engine can tune away. `hipGraph` replay measured
  2.83 us/node in EXP-0073 — the graph removes launch cost, but the *round trip*
  to the host is what dominates here, and a graph cannot remove it when the host
  must compute between nodes.
- Zero-copy (`hipHostMallocMapped|Coherent` + `hipHostGetDevicePointer`) wins:
  no explicit copy at all, the kernel touches host memory over PCIe directly.
  Upload/download disappears (11.2 vs 46.6 us) but the sync remains, so the
  realistic figure is **28.5 us** per switch, and 1114 us per 40-layer token.
- Pinned staging is not worth the extra buffer management: 1240 vs 1114 us.

**Adopted: 28 us per handoff.** EXP-0080's curve with that term added:

| VRAM | today | ideal | chain | tok/s | dependency cost |
|---|---|---|---|---|---|
| 0 | 26.0 | 26.0 | 27.1 | 36.9 | 1.04x |
| 2 GB | 25.2 | 12.8 | 14.1 | **70.9** | 1.10x |
| 8 GB | 20.1 | 7.7 | 9.7 | **103.3** | 1.25x |
| 16 GB | 15.4 | 3.2 | 7.9 | 126.8 | 2.46x |

(24B model, 4128-token prefix, 280 GB/s.)

The tax is 1.12 ms/token, so it is 8% of a 2 GB token and 12% of an 8 GB one.
It does not change the conclusion: a 2 GB card still buys 1.9x and an 8 GB card
2.8x. But it does mean the win **saturates**: at 16 GB the dependency cost is
2.46x, i.e. a card with twice the bandwidth of 8 GB delivers only 1.23x, because
each layer still waits for its 1.12 ms of nothing.

## Lesson

The cost that decides a hybrid's viability was not the copy — it was the
**round trip**. A model that prices bytes and not synchronisations overstates
every offload design, and the error grows as the offloaded share shrinks, which
is exactly the regime consumer cards live in.
