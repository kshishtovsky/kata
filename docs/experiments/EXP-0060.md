# EXP-0060 — one 4-way horizontal reduce instead of four serial ones: core 1.17x

Status: PASSED
Date: 2026-11-27

## Problem

`prefill_group4` scored four heads per kv position and called
`_mm512_reduce_add_ps` four times, once per head. At a 16k prefix, 1024-token
chunk that is 1024 x 16896 x 8 = 138.4 M score vectors and therefore 553 M
serial horizontal reductions. Each is ~6 dependent uops, and they are on the
critical path between the QK FMAs and the softmax.

## Fix

`src/prefill.cpp`: keep the four dot products in `__m512 a[G]`, fold them to
four `__m256` with `_mm512_extractf32x8_ps` + `add_ps`, then one
`_mm256_hadd_ps(h01, h23)` pair and a single cross-lane add. The result lands in
an `__m128` already holding `[sc0, sc1, sc2, sc3]`, which `exp128_ps` consumes
directly, so the scale multiply also becomes one vector op. Requires `avx512dq`
in the target attribute for `_mm512_extractf32x8_ps`.

## Measurement

Isolated `attention_prefill_mt`, engine shape (32 heads / 8 kv heads / hd 64),
taskset -c 0-15, best of 3, prefix + chunk:

| prefix | threads | before | after | |
|---|---|---|---|---|
| 8192 | 16 | 96.5 ms | 80.3 ms | 1.20x |
| 16384 | 16 | 178.5 ms | 152.2 ms | **1.17x** |
| 16384 | 1 | 2474 ms | 2231.8 ms | 1.11x |
| 16384 | 8 | 330.2 ms | 297.8 ms | 1.11x |

Engine, full 16384-token prefill, summed over all 16 chunks, `KATA_PROF=1`:
attention core 13785 -> **12878 ms**. Wall clock is dominated by the FFN and
moves within noise (425.5 -> 425.8 tok/s median of three runs).

Logit shifted 28.45286 -> 28.35602 on the 16384-token prompt because the
summation order changed; `argmax` is unchanged at 17778. This is the accepted
fp32-reassociation class of difference, same as the ubatch sweep in EXP-0055.

## Instruction accounting (why only 1.17x)

Per (query row, kv position, group of 4 heads): 32 zmm FMA of real work, plus
8 loads, 4 broadcasts, ~12 uops of reduce and ~10 of vector exp. That is 32 FMA
in ~66 uops. Measured 4.43 G zmm FMA over 12.2 G core cycles = 0.36 FMA/cycle
against a 1.0/cycle zmm peak, i.e. 64% of cycles are still not-FMA. The reduce
was the largest single non-FMA item and is now amortised 4:1; what remains is
spread across the exp, the broadcasts and the loads, so no single next step is
worth more than a few percent.
