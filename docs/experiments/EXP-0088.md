# EXP-0088 — what the host router inside the layer loop actually costs

**Status:** PASSED (0.655 ms of waits, token 99.5 tok/s; the wait removal also hides launches)
**Date:** 2026-11-27

## Problem

EXP-0087 left the MoE stage at 2.404 ms with one identified cost: 38 synchronisations
per token, because the CPU router sits inside the layer loop and each layer's
experts must be decided before that layer's launches. EXP-0086 priced a handoff at
22.5 us, but that number included the transfer; the *wait* alone was never isolated.

## Method

`bench/hip/bench_moe_gpu.hip`, arm E: identical work to arm D (152 launches,
pointer arrays, device combine) with the per-layer `hipDeviceSynchronize` removed —
one sync for the whole token. This is the floor a device router can reach, not a
router: the activation row is constant across layers, which is exactly the
dependency a real router would have to satisfy anyway.

A real device router adds, per layer, one 2048-wide dot per expert against
`ffn_gate_inp` — 0.5 MB of weights against this arm's 24 MB of expert stream, so
2% of the traffic. The floor is therefore close to the achievable number.

## Result

| arm | ms/token | launches | waits |
|---|---|---|---|
| D pointers + device combine | 2.404 | 152 | 38 |
| **E no per-layer wait** | **1.749** | 152 | **1** |

```
D - E = 0.655 ms = 17.2 us x 38 layers
token: 22.50 - 14.20 + 1.749 = 10.05 ms = 99.5 tok/s  (vs 43.9 today, 2.27x)
```

## Analysis

- **The wait is 17.2 us, not 22.5 us.** EXP-0086's 22.5 us bundled the transfer and
  the sync; separated, the sync is 17.2 and the 32 KB copy was ~5 us. Consistent,
  and worth recording because the two have different fixes (copy -> device combine,
  done in EXP-0087; sync -> device router).
- **Removing the waits also recovered launch cost**: E is 0.655 ms faster than D,
  but 38 waits at 17.2 us is exactly 0.655 ms — so the launches were already free
  once the host stopped waiting between them. With a sync every layer the queue
  drains; without it, the driver keeps the queue full and 152 launches cost
  approximately nothing.
- **The per-layer pointer slots make a device router easy.** EXP-0087's fix (each
  layer owns slabs `[l*4, (l+1)*4)`) means a router kernel only has to write four
  pointers into the next layer's slot. No relocation, no second copy of the
  weights.
- A device router is now the only remaining MoE cost of consequence: 1.749 ms to
  1.75 ms + 38 x (one 2048-wide dot + top-4 selection) — sub-microsecond work per
  layer at these sizes.

## Traps

- Measuring "no sync" as a speedup invites the reverse error: if the arm had
  dropped the weighted sum too, the 0.655 ms would have been attributed to the
  wrong component. The only difference between D and E is the sync placement.
- `bench` here runs five reps of a fully asynchronous pass and syncs once at the
  end of each rep, which is what a real pipelined token looks like; timing a
  single rep without any sync would measure enqueue time and read as a fake
  speedup.

## Conclusion

Keep. The MoE stage is 1.749 ms and the remaining cost is the router itself, which
is now cheap to move. That closes the ladder the last seven experiments climbed:

| | ms/token | x vs CPU MoE (14.20) |
|---|---|---|
| EXP-0082 arithmetic only | 1.690 | 8.40x |
| EXP-0086 real pipeline | 3.663 | 3.87x |
| EXP-0087 pointer launches + join | 2.404 | 5.90x |
| EXP-0088 no host wait | 1.749 | 8.12x |

Whole token with a device router and resident weights: **~10.0 ms = 99.5 tok/s**
against 43.9 today, before attention and glue are moved — which is the next
experiment, and the one that decides whether this becomes a backend or stays a
benchmark.
