# EXP-0059 — one fan-out for the MoE gate+up pair: +3.6% prefill 16k

Status: PASSED
Date: 2026-11-27

## Problem

`moe_ffn_rows` called `mmn` twice per expert bucket for gate and up. Both
projections read the SAME `aq_g` activation rows, so
`gemm_q4_K_q8_K_mt` packed the same activation tiles twice and woke the pool
twice, per bucket, 1748-1756 buckets per 1024-token chunk.

## Fix

`gemm_q4_K_q8_K_mt2(m, n_a, n_b, k, out_a, lda, w_a, out_b, ldb, w_b, a, pool)`
in `src/gemm.cpp`: one pack across the pool, then one fan-out where each worker
takes the same weight-row range in BOTH matrices, so its unpacked bands stay hot.
`moe_ffn_rows` uses it when both projections are q4_K, and falls back to two
`mmn` calls otherwise.

## Where the rest goes

The attention core is the larger remaining item at long context. Full 16k run,
summed over all 16 chunks: attention stage 15127 ms (core 13785), FFN 19127 ms,
total 40.3 s.

Instruction accounting for the core at a 16k prefix, 1024-token chunk, per
(query row, position, kv group of 4 heads): 32 zmm FMA of real work, but also
4x `_mm512_reduce_add_ps` (~6 uops each), 8 loads, 4 broadcasts, one `exp128_ps`.
That is 32 FMA in ~77 uops = 41% issue occupancy, which matches the measured
397 GMAC/s against the 1288 GMAC/s fp32 peak (31%). The reduce is the single
largest non-FMA cost and the next target.
